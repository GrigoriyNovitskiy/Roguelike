
# RogueLike
## 1. Общие сведения о системе:
### Назначение
Игра в жанре RogueLike
### Контекст, в котором существует система
Игра должна запускаться из консоли

## 2. Architectural Drivers

### Технические ограничения:
* Исключительно консольная графика (ASCII/ANSI)
* Кроссплатформенность (Linux/Windows/macOS)
* Использование стандартной библиотеки языка + минимальные зависимости

### Бизнес-ограничения:
* **Бюджет**: Только бесплатные инструменты и библиотеки
* **Время**: Ограниченные сроки разработки
* **Команда**: 1-3 разработчика (full-stack подход)
* **Лицензия**: Open-source (MIT License)

### Качественные характеристики:
1. **Расширяемость**:
   - Модульная архитектура
   - Четкие интерфейсы между компонентами
   - Использование паттернов (ECS, Dependency Injection)

2. **Поддерживаемость**:
   - Полная документация (API, архитектура)
   - Автоматизированные тесты (70%+ coverage)
   - CI/CD пайплайн

3. **Производительность**:
   - Минимальные требования (даже для старых ПК)
   - Оптимизация не в приоритете (пошаговая механика)

4. **Безопасность**:
   - Локальное хранение данных
   - Нет сетевого взаимодействия
   - Нет чувствительных данных пользователя

### Ключевые функциональные требования:
| Категория       | Требования                                                                 |
|-----------------|---------------------------------------------------------------------------|
| Графика         | ASCII-рендеринг, цветной вывод, поддержка 80x25 терминала                 |
| Управление      | Keyboard-only input (vim-подобные клавиши: hjkl)                          |
| Игровой мир     | Загрузка карт из .txt файлов + процедурная генерация                      |
| Персонаж        | Единственный управляемый герой с инвентарем                               |
| Объекты         | Иерархия: Entity > Actor/Item/Obstacle с полями позиции и характеристик   |
| Сохранения      | Только ручное сохранение при выходе (autosave)                            |
| Интерфейс       | 3 основных экрана: Главное меню, Игровое меню, Игровой экран              |
| Модификации     | Поддержка модов через загрузку JSON-конфигов                              |

## 3. Роли и случаи использования

### Основные роли:
1. **Разработчик**:
   - Реализация игровой логики
   - Создание контента (карты, предметы)
   - Поддержка кодовой базы

2. **Игрок**:
   - Прохождение процедурно генерируемых уровней
   - Управление персонажем и инвентарем
   - Взаимодействие с игровыми системами

### Профиль целевого пользователя:
* **Демография**: 18-35 лет, технически подкованные
* **Платформа**: Преимущественно Linux (80%), возможно Windows/macOS
* **Мотивация**:
  - Нетребовательная к ресурсам игра
  - Возможность играть в терминале/SSH-сессии
  - Ностальгия по классическим roguelike
* **Ограничения**:
  - Слабые hardware-ресурсы
  - Отсутствие графического ускорителя
  - Ограниченное дисковое пространство

### Ключевые сценарии использования:
1. **Старт игры**:
   - Загрузка начального уровня
   - Инициализация персонажа
   - Рендеринг стартового экрана

2. **Игровой процесс**:
   ```mermaid
   sequenceDiagram
     Игрок->>Движок: Нажатие клавиши (например 'h' - влево)

     Физика->>Уровень: Проверка клетки (x-1,y)

   - Подбор предметов (автоматический)

4. **Сохранение**:
   - Автосохранение при выходе
   - Загрузка последнего состояния

### Основные компоненты

#### Модель (Игровая логика)
**Основные обязанности**:
- Управление состоянием игры
- Обработка игровых правил и механик
- Генерация и управление игровым миром

**Подсистемы**:
- `СостояниеИгры`: Отслеживает текущий статус (меню/игра/пауза)

- `ГенераторМира`: Процедурная генерация уровней

#### Контроллер (Обработка ввода)
**Функционал**:
- Преобразование нажатий клавиш в действия
- Управление очередью команд
- Координация модели и представления

#### Render (Отрисовка)
**Задачи**:
- Визуализация игрового состояния 
- Управление интерфейсом
- Вывод в терминал
**процесс отрисовки**:
- Получение состояния игры
- Формирование ASCII-изображения
- Применение цветов и эффектов

## 6. Логическая структура (диаграмма классов с описанием)

[Диаграмма](./docs/Logic.svg)

Диаграмма классов разделена на три основных части: Controller, Model и View.

## 1. Controller (Управление)
Отвечает за логику управления игровым процессом.

### Основные классы:
- `GameController` - главный управляющий класс
- `GameSaver` - сохранение игры
- `GameLoader` - загрузка игры
- `Generator` - генератор игровых элементов

## 2. Model (Данные и логика)
Содержит игровые сущности и логику.

### Игровые объекты:
- `Game` - основное состояние игры
- `Field` - игровое поле
- `Position` - координаты объектов

### Участники игры:
- `Player` - игрок
- `Monster` - противник
- `Ability` - способности
- `Stats` - характеристики

### Фабрики:
- `MonsterFactory` - создание монстров
- `HumanFactory` - создание игроков
- `BossFactory` - создание боссов

### Стратегии поведения:
- `RandomStrategy` - случайное поведение
- `PassiveStrategy` - пассивное поведение
- `AggressiveStrategy` - агрессивное поведение

### Типы ячеек:
- `EmptyCell` - пустая
- `HealCell` - лечение
- `Food` - еда
- `ObstacleCell` - препятствие
- `Wall` - стена

## 3. View (Отображение)
Отвечает за визуальную часть.

### Системы отрисовки:
- `MainMenuDrawer` - главное меню
- `GameMenuDrawer` - игровое меню
- `GameDrawer` - игровой процесс

## Взаимодействия:
1. `GameController` → `Game` → `Field`
2. `Field` состоит из ячеек (`InterfaceCell`)
3. `Player`/`Monster` используют `Ability` и `Stats`
4. `Generator` создает объекты через фабрики
5. Персонажи используют стратегии поведения

## 7. Взаимодействия и состояния (диаграммы последовательностей и конечных автоматов с описаниями)

[Диаграмма](./docs/Sequence.svg)

## 1. Начало игры (Start Game)

**Участники:**
- Игрок (Player)
- Контроллер (GameController)
- Модель (Game)
- Представление (GameView)

**Последовательность действий:**
1. Игрок → Контроллер: "Start game"
2. Контроллер → Модель: "Initialize game"
3. Модель:
   - Создает игровое поле
   - Генерирует начальные объекты
4. Модель → Представление: "Update game state"
5. Представление → Игрок: Отображает игровое поле

   ```mermaid
   sequenceDiagram
      participant User
      participant Controller
      participant Model
      participant View
      
      User->>Controller: "Exit"
      Controller->>Model: "Exit"
      Model->>Model: Очистка поля
      Model->>View: "Clean field"
      View->>User: Очищает экран

## 2. Выход из игры (Exit Game)

**Участники:**
- Игрок (Player)
- Контроллер (GameController)
- Модель (Game)
- Представление (GameView)

**Последовательность действий:**
1. Игрок → Контроллер: "Exit game"
2. Контроллер → Модель: "Terminate game"
3. Модель:
   - Сохраняет состояние (если нужно)
   - Очищает игровые данные
4. Модель → Представление: "Clean view"
5. Представление → Игрок: Показывает главное меню

   ```mermaid
   sequenceDiagram
      participant User
      participant Controller
      participant Model
      participant View
      
      User->>Controller: "Make move"
      Controller->>Model: "Change field"
      Model->>Model: Обновление состояния
      Model->>View: "Update field"
      View->>User: Показывает новое состояние

## 3. Выполнение хода (Make Move)

**Участники:**
- Игрок (Player)
- Контроллер (GameController)
- Модель (Game)
- Представление (GameView)

**Последовательность действий:**
1. Игрок → Контроллер: "Move to [position]"
2. Контроллер → Модель: "Process move"
3. Модель:
   - Проверяет валидность хода
   - Обновляет позиции объектов
   - Проверяет игровые события
4. Модель → Представление: "Update view"
5. Представление → Игрок: Отображает новое состояние

## 8. Описание игровых данных

## 1. Данные персонажа (Player)
- **Позиция**: координаты (x, y) на карте
- **Характеристики**:
  - Здоровье (текущее/максимальное)
  - Мана (если есть)
  - Сила атаки, защита, уклонение
  - Скорость передвижения
- **Инвентарь**: список предметов
- **Экипировка**: предметы в слотах (оружие, броня и т.д.)
- **Прогресс**:
  - Уровень
  - Опыт
- **Состояния** (опционально):
  - Голод
  - Отравление
  - Эффекты

## 2. Данные монстров/NPC
- **Тип**: идентификатор существа
- **Позиция**: координаты (x, y)
- **Характеристики** (аналогично игроку)
- **Поведение AI**:
  - Агрессивный
  - Пассивный
  - Убегающий
- **Лут**: предметы после смерти
- **Диалоги** (для NPC)

## 3. Данные предметов
- **Идентификатор**: уникальный ID
- **Название и описание**
- **Тип**:
  - Оружие
  - Броня
  - Зелья
  - Свитки
  - Еда
- **Свойства**:
  - Для оружия: урон, тип урона
  - Для брони: защита, слот
  - Для расходников: эффекты
- **Вес и стоимость** (для торговли)
- **Графика**: символ и цвет для отображения

## 4. Данные карты
- **Размеры**: ширина и высота
- **Тайлы**:
  - Тип (стена, пол, вода)
  - Проходимость
  - Прозрачность
- **Объекты**:
  - Лестницы
  - Сундуки
  - Алтари
- **Исследованные области**
- **Предметы на земле**
- **Монстры/NPC** на уровне

## 5. Данные квестов
- **Идентификатор и название**
- **Тип**:
  - Убить N монстров
  - Найти предмет
  - Достичь точки
- **Цели**: условия выполнения
- **Награды**:
  - Опыт
  - Предметы
  - Деньги
- **Статус**:
  - Не взят
  - Активен
  - Выполнен
  - Провален

## 6. Конфигурационные данные
- **Шаблоны**:
  - Монстров
  - Предметов
  - Квестов
- **Предустановленные карты**
- **Настройки**:
  - Сложность
  - Управление
  - Графика

## 7. Состояние игры (для сохранения)
- **Текущий уровень**
- **Состояние игрока**
- **Состояние сущностей**
- **Расположение предметов**
- **Прогресс квестов**

## Форматы хранения
- **JSON/XML** для шаблонов
- **Бинарные файлы** для сохранений
- **Конфиги** в INI/JSON формате

## Особенности
